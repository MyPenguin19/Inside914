Inside914 — local category/schema foundation
Date: 2026-10-19

Completed scope

Added and applied the category foundation to the existing isolated localhost
Supabase database. This is a schema/API foundation; the customer-facing category
selection flow is not connected yet. UI, styles, postcard geometry, prices and
payment integrations are unchanged. The broader MVP revision is not complete.

Implementation

- Added advertising_categories with 12 normalized reference identifiers:
  plumbing, hvac, landscaping, real-estate, dental, restaurant, pet-care,
  auto-repair, roofing, electrician, cleaning and pest-control.
  The catalog has RLS and public read-only access. No unrestricted category text
  is used for exclusivity. No category override was added.
- Added editions.category_exclusivity, default false. Only an unused draft can
  opt in, through an authenticated admin RPC that writes an audit event. An
  enabled campaign cannot turn the protection off. No existing campaign was
  opted in or changed to a different status.
- Added bookings.category_id with a foreign key and a partial unique index on
  campaign/category for active bookings. The index protects direct database
  writes as well as the new RPC. No legacy categories were guessed or backfilled.
- Added a deferred database constraint so category-enabled transactions cannot
  commit an active booking without a category. Existing hold functions therefore
  cannot bypass the requirement. Assigned categories cannot be changed or removed;
  released/canceled categorized bookings cannot be reopened.
- Added service-only hold_category_cart for one to four distinct areas. It wraps
  the existing cart/slot implementation, uses deterministic locking and releases
  expired same-category holds before reassignment. Any conflict rolls back the
  entire new group. Cancellation releases that zone's claim independently.
- Added category_availability, exposing only campaign/zone/category and
  available/held/reserved/closed status. It does not expose advertiser identities,
  contacts, tokens or payment details. Private draft campaigns remain hidden.
- Existing confirmation, consent checks, slot allocation, hold expiry and
  cancellation remain in use. No customer account is required by the new RPC.

Important boundaries

Exclusivity is per zone campaign/edition, so a future campaign can accept a new
reservation in the same category. A reservation group cannot select the same
zone twice. Existing campaigns remain legacy-compatible and unmodified.

The new category hold entry point accepts single standard positions only. It
does not approve a physical layout, create ten-position inventory, disconnect
legacy customer routes, or implement the later $399 pricing/customer-flow slice.
It deliberately retains existing pricing behavior until that revision is made.
The server that connects this RPC to a customer flow must use the existing
rate-limit and secure cart-token conventions; public clients cannot call it.
