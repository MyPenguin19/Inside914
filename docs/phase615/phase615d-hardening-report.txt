FINDINGS BY SEVERITY
CRITICAL — Short-lived recovery depended on a daily fallback that could outlive the token. Fixed with bounded immediate dispatch, exact database expiry, a pre-send validity margin, deduplicated preparation and safe explicit customer resubmission. Provider outages longer than token lifetime still require a fresh user request or support; daily cron is not advertised as a recovery SLA.
CRITICAL — Original consent had no immutable deadline snapshot or fail-closed review for later extensions/draft wording. Fixed for new consent with a database snapshot/immutability trigger and collection guards. Historical deadlines are deliberately not invented. Legacy records with unknown authorization, extended dates or unresolved draft versions are blocked from collection. Owner/counsel decisions and a reviewed explicit renewal path remain release prerequisites.
HIGH — Terminal failed emails could occupy the oldest preparation batch forever and starve new confirmations. Fixed with an outbox-to-delivery anti-join; existing durable messages are handled only by the delivery worker. Batch failures are isolated.
HIGH — Duplicate recovery submissions could issue multiple tokens/envelopes immediately; provider retries and late events needed stricter handling. Fixed with serialized one-minute preparation deduplication, stable encrypted content/idempotency keys, sticky ambiguous outcomes, lease fencing and bounded attempts. Delivered/adverse outcomes no longer regress on later positive/intermediate events.
HIGH — Owner alerts relied primarily on daily delivery and first terminal failures could remain unnoticed. Fixed with managed after-response dispatch backed by transactional in-app alerts, nonrecursive failure visibility, durable retries and an explicit missing-address warning. Event-triggered delivery has documented runtime/batch limits; unattended deadlines still rely on the daily job.
HIGH — Production EMAIL_PAYLOAD_ENCRYPTION_KEY, RESEND_WEBHOOK_SECRET and ADMIN_NOTIFICATION_EMAIL are absent; no Inside914 outbound Resend webhook exists. OPEN ROLLOUT BLOCKER: exact setup and secure verification are documented, not silently configured. Domain inside914.com is verified. Existing secret validity/inbox delivery remains unverified without an approved controlled provider test.
HIGH — New checkout terms remain drafts and differ materially from earlier deadline promises. OPEN COMMERCIAL-LAUNCH BLOCKER: preserve draft notices and archived versions; approve final policy/version and applicable renewed authorization before public commercial release. Collection-disabled is not a substitute for approved checkout policy.
MEDIUM — Browser refresh forgot a previously used cart extension. Fixed by passing the persisted extension count; SQL rejects extensions that add no time. The shared hold remains capped at 45 minutes and the earliest campaign deadline.
MEDIUM — Historical charged bookings without a matching ledger could be presented as unpaid, and a test ledger could look like a live charge. Fixed with explicit unverified/test states; removed the obsolete admin claim that collection was not built.
MEDIUM — Invitation send state could carry into the next preview, and a scheduling failure could misreport an already-queued invitation as failed. Fixed with keyed preview send state and durable-queue fallback. Expiry, changed price, occupied position and paused/closed campaign are revalidated.
MEDIUM — Webhook size was bounded after reading the entire body. Fixed with bounded streaming; unsupported signed event types are acknowledged without DB work.
LOW / OPERATIONAL — Provider acceptance is not guaranteed inbox delivery; previously issued evidence URLs can remain usable for their 60-second lifetime after unpublication. Neither limit is described as stronger protection than it provides. Final printer acceptance and mailing quantities remain separate approvals.

EMAIL / RECOVERY VERIFICATION
Stable logical key -> one encrypted immutable envelope -> fenced lease -> accepted, failed or investigation. The payload and provider idempotency key remain identical across retries. A timeout before or after possible acceptance is ambiguous; retries stop before the provider's 24-hour retention boundary. An old delivery that never started does not spend that retention window. Late signed events reconcile a crashed/expired worker without requiring another send. Missing encryption key preserves the ciphertext and raises investigation; it does not revoke potentially delivered access links. Maximum eight persisted attempts; terminal and ambiguous outcomes remain visible.
Recovery choice is bounded pathway B: two provider attempts at most, ten seconds each and one-second pause; no silent regeneration. At least one minute must remain before dispatch. A provider can delay an accepted message beyond that margin; the generic form explains 15-minute expiry and safe resubmission. Three requests per email/hour and ten per IP/hour remain; single-use token exchange is serialized. Existing valid reservation sessions are not revoked. Parallel exchange creates only one session for the consumed token. A later deliberate recovery request may coexist with prior still-valid access.
Focused tests cover success, before/after-acceptance timeout, 429, 5xx, permanent rejection, outage, expired queue, lost key, concurrent workers/submissions/exchanges, lease expiry, invalid reference/email, used/expired tokens and duplicate/out-of-order events. No provider email or payment was used.

WEBHOOK SECURITY
Validated against Resend's published outbound event schema and Svix protocol, not just old mocks. Raw HMAC verification, constant-time comparison, five-minute timestamp tolerance, strict signing configuration, 256-KiB streamed limit, unique event IDs and provider/delivery identity checks. data.tags is an object and the delivery_id tag is optional; fallback uses a previously recorded provider ID. No recipient-based association. Unknown valid event types do not reach DB mutation. No contact, token, secret, signed URL or raw body is logged. Signed negative outcomes remain visible and do not get cleared by later sent/delivered noise.
