  Events email.sent, email.delivered, email.delivery_delayed, email.bounced,
         email.complained, email.failed, email.suppressed.
Payload contract: type, created_at, data.email_id; optional data.tags is a string-key/string-value object. The delivery_id tag is associated with a known delivery; otherwise lookup uses the known provider message ID. Never associate using recipient email alone.
Signature headers svix-id, svix-timestamp, svix-signature; raw request body; five-minute past/future tolerance; bounded 256-KiB body. Authenticated unsupported types are acknowledged without database mutation. Retain event-ID deduplication and message-ID mismatch rejection.
Initial delivery verification requires a separately approved owner-controlled recipient and one explicit message. Test signature reconciliation, delivery and duplicate event handling; do not email real customers or run the whole production outbox as a smoke test.

Project is documented as Hobby. Current Vercel docs allow daily jobs on Hobby with timing variation up to 59 minutes; a daily worker cannot promise recovery within a 15-minute token lifetime.
Managed Next after() attempts prompt delivery; durable rows survive callback failure. Recovery sends twice at most using the same envelope/key and a ten-second HTTP timeout per attempt. A usable link needs at least 60 seconds remaining before dispatch. Accepted provider delivery may still be delayed; no inbox latency or exactly-once guarantee.
Owner notifications drain at most six due messages per prompt job; remaining work waits for another event/job. In-app alerts remain authoritative. Decide whether this fallback latency meets the launch SLA; faster unattended scheduling requires a separately approved plan or scheduler. No automation was created here.
